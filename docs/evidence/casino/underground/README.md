# The Underground, photographed

Captured by `npm run visual:qa` on 2026-08-12 — **129 states × 3 widths, 387
captures, 0 failures** — against a production build, a real Postgres and the
real server actions. The demo seat wagers real (fictional) tokens and the
blackjack hand is a genuine `blackjack_hands` row.

**The Underground is CLOSED.** Every one of these needs
`?open=underground[,slotMachine|,blackjackTable]`, which `lib/flags.ts` resolves
**server-side** behind the demo system's two guards and refuses outright when
`VERCEL_ENV=production`. No real manager can reach any of it.

| File | State |
|---|---|
| `*-underground.png` | The room with the machine live and the table covered — what shipping W1 alone looks like |
| `*-underground-covered.png` | Both machines covered. The room on the day the door opens before either game is switched on, and the room a revert produces |
| `*-underground-blackjack.png` | **A hand actually dealt.** Cards, totals, Hit and Stand — a screenshot of a form is not a test of the form |
| `390-back-hall-both-open.png` | Both Back Hall doors open. Recorded as *"a demo this document asked for and the product cannot honestly produce"* since the hall was built; the casino brought its route and the state arrived with it |

**All three widths for each**, because the room is judged at true phone size
(`MANDATE §7`).

One thing to notice in `underground-blackjack`: the three widths photograph **the
same hand**. Only one hand may be open per manager, so the second and third
widths resume the row the first one dealt rather than dealing their own — which
is the multi-device property, photographed without anybody arranging it.
